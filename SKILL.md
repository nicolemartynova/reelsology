# Рилсология

Навык состоит из двух частей, они дополняют друг друга:

- **Приёмы:** что снять, написать и смонтировать, чтобы рилс смотрели. Это база знаний, она растёт из рилсов, которые присылает пользователь. Режимы: **обучение**, **каталог**, **применение**, **совет**, **сценарий**, **статистика**. Каждый разбор ищет приёмы и в монтаже, и в тексте.
- **Техника:** как довести ролик до площадки и не испортить картинку и звук. Это конвейер от дубля до готовых файлов и проверка по стандарту сдачи. Раздел «Техника» ниже.

Ролик проходит через обе части: приёмы задают, что делать, техника следит, чтобы результат дошёл до зрителя без потерь.

Папка навыка: `~/.claude/skills/reelsology/`.
- `functions/<ID>-<slug>.md` — карточки функций. Это и есть база.
- `sources/<дата>-<slug>.md` — разбор каждого присланного рилса.
- `principles.md` — общие правила рилсологии, которые повторяются в нескольких рилсах. Каждое помечено: универсальное, зависит от формата или зависит от ниши.
- `checklist.md` — универсальный чек-лист для любой ниши.
- `resources.md` — сервисы для мемов, фраз из фильмов и стоков.
- `sounds.md` — словарь звуков: задача → звук → куда ставить → по какому слову искать → где брать легально.
- Библиотека звуков пользователя — своя у каждого, вне навыка (по умолчанию `~/reels-sfx/`, путь: `python3 scripts/sfx.py where`). Режим 7. При монтаже звук берётся оттуда в первую очередь.
- Расстановка и сведение звуков — навык `real-sfx` (`~/.claude/skills/real-sfx`): порядок в `sounds.md`, раздел «Расстановка и сведение».
- `niches/<ниша>.md` — то, что в разных нишах выглядит по-разному: чем доказывать, форматы, хуки, призыв, ограничения.
- `stats.md` — просмотры и лайки разобранных рилсов (режим 6).
- `CATALOG.md` — список функций. Генерируется скриптом, руками не править.
- `pipeline/` — техника: `starter/` (чистый проект монтажа без стиля), `scripts/` (кладутся в проект), `references/delivery-standard.md` (стандарт файла), `references/incidents.md` (журнал ошибок).
- `work/` — скачанные видео, кадры, расшифровки. Не в git: чужие ролики только для разбора, никуда не публикуются.

Общение — по-русски, простыми словами.

## Категории функций

| Код | Категория | Что сюда |
|---|---|---|
| Х | Хуки | первые 1–3 секунды: что видит и слышит зритель до решения листать |
| У | Удержание | ритм, открытые петли, смена плана, паттерн-прерывания, обещания «дальше» |
| М | Монтаж | склейки, панч-ины, джамп-каты, переходы, темп, b-roll |
| Т | Текст и субтитры | вид субтитров, выделение слов, заголовки, плашки |
| Г | Графика и движение | карточки, стрелки, анимация, стикеры, эффекты |
| З | Звук | музыка, звуковые эффекты, паузы, громкость, обработка голоса |
| С | Сценарий и подача | структура, формулировки, интонация, призыв к действию, концовка |
| В | Вкус | цвет, свет, кадр, композиция, общий стиль |

ID функции = код + номер: `Х-01`, `М-12`. Следующий свободный номер: `python3 scripts/catalog.py --next М`.

## Настройка: «настрой», «создай проект», «хочу монтировать через Claude Code»

Нужна один раз, только для монтажа. Разборы, сценарии и советы работают без неё. Если пользователь просит смонтировать ролик, а проекта монтажа ещё нет, начни отсюда.

1. Спроси, где создать проект (например, `~/reels`). Папка должна быть новой или пустой: чужие файлы не перезаписывай.
2. Создай проект:
   ```bash
   P=~/reels
   mkdir -p "$P" && cp -R ~/.claude/skills/reelsology/pipeline/starter/. "$P/"
   mkdir -p "$P/video/scripts" && cp ~/.claude/skills/reelsology/pipeline/scripts/* "$P/video/scripts/"
   ```
3. Прочитай `"$P/.claude/skills/setup/SKILL.md"` и выполни его как инструкцию. Там проверка окружения, установка недостающего (Node.js, Remotion, ffmpeg, whisper или ElevenLabs, rembg) только после «да», интервью о стиле и показ вариантов кадрами.
4. В конце попроси перезапустить Claude Code в папке проекта: подхватятся навыки Remotion, субагенты и хук.

У проекта нет своего стиля. Цвета, шрифты, субтитры, графику и звук выбирает человек или они берутся из его референсов. Профиль лежит в `video/reels.config.json`, `brand-kit.md` и `editing-taste.md`: из него берутся голос и тон для сценариев.

## Режим 1. Обучение: «разбери рилс <ссылка>»

1. **Скачать и измерить**:
   ```bash
   python3 ~/.claude/skills/reelsology/scripts/intake.py <ссылка или файл>
   ```
   Если Instagram требует вход — спросить пользователя и только с его согласия запустить с `COOKIES_FROM=chrome`. Скрипт печатает папку `work/<slug>/`, в ней:
   - `analysis.md` — расшифровка по фразам с таймкодами, склейки, длины планов, темп речи, громкость по секундам;
   - `hook.jpg` — первые 3 секунды, кадр каждые 0,25 с;
   - `shots-N.jpg` — первый кадр каждого плана с таймкодом;
   - `overview-N.jpg` — кадр каждую секунду.
2. **Определить нишу** рилса и записать её в разбор (`niche:`). Если ниша новая, то после 5+ рилсов создать для неё `niches/<ниша>.md` (см. `niches/README.md`).
3. **Посмотреть ролик целиком**: прочитать `analysis.md` и **все** листы кадров (Read). Ничего не выдумывать — каждый вывод опирается на таймкод, кадр или фразу.
   Whisper на музыке без речи иногда выдумывает текст («Субтитры сделал…», «Transcription by…») — такие фразы сверять с кадрами и отбрасывать. Текст на экране читать с кадров, а не из расшифровки.
4. **Разделить два слоя**:
   - что рилс **говорит** (если он обучающий: приёмы, которые объясняет автор);
   - что рилс **делает** сам (как он смонтирован: хук, склейки, субтитры, графика, звук, структура).
   Оба слоя — источники функций.
5. **Выделить функции**. Функция — один конкретный повторяемый приём, который можно выполнить по инструкции. «Динамичный монтаж» — не функция. «Панч-ин 1.0 → 1.15 на каждой склейке в первых 5 секундах» — функция.
6. **Проверить базу на дубли**: `grep -ril "<ключевые слова>" functions/`. Если приём уже есть — **дополнить** существующую карточку (новый источник, пример, уточнённые параметры), а не создавать копию. Если найден вариант приёма — отдельная карточка со ссылкой на родственную.
7. **Записать** новые карточки по шаблону `templates/function.md`, разбор рилса по шаблону `templates/source.md`.
8. Если правило подтвердилось в 3+ рилсах — добавить или усилить его в `principles.md` со ссылками на функции.
9. **Обновить каталог и сохранить.** Если подключён Apify (режим 6), сначала `python3 scripts/apify.py stats <ID новых рилсов>`, чтобы у разборов были просмотры:
   ```bash
   cd ~/.claude/skills/reelsology && python3 scripts/catalog.py && git add -A && git commit -m "Разбор: <slug>" && git push
   ```
10. **Ответить пользователю**: что за рилс (одной строкой), список новых и дополненных функций с ID и одной фразой о каждой, что из этого стоит попробовать первым в его роликах.

## Режим 2. Каталог: «список функций», «что мы знаем про хуки»

- Весь список: показать `CATALOG.md` (по категориям, ID, название, одна фраза, сколько рилсов подтверждают).
- Одна категория: только её раздел.
- Одна функция («расскажи про У-04»): карточку целиком, простыми словами.

## Режим 3. Применение: «сделай функцию М-03»

1. Открыть карточку, перечитать раздел «Как сделать» и «Когда не применять».
2. Понять, к какому ролику применять: текущий проект Remotion пользователя. Если непонятно — спросить.
3. Выполнить по шагам карточки. Техническую часть (нарезка, мастер, сдача) — по разделу «Техника» этого навыка, со всеми его проверками. Цвета, шрифты и стиль — только из профиля пользователя, функция задаёт приём, а не чужой бренд.
4. Показать результат кадром или черновиком. Если по ходу стало ясно, как делать лучше, — дописать в карточку раздел «Опыт применения».

## Режим 4. Совет: «как лучше смонтировать / написать / снять этот рилс»

1. Сначала база: `checklist.md` и `principles.md`, затем подходящие функции из `CATALOG.md` и их карточки. Понять нишу ролика и открыть `niches/<ниша>.md`. Если файла ниши нет, советовать только универсальное и сказать, что по этой нише в базе данных нет. Примеры в ответе брать из ниши пользователя, а не из ниши источника: в базе почти все рилсы учат делать рилсы, и их приёмы доказательства (цифра просмотров, «этот ролик тоже так построен») в других нишах нужно переводить на язык ниши.
2. Ответ — конкретный план под задачу пользователя: хук (какая функция и как), структура по секундам, монтаж, текст, звук, концовка. Каждый пункт со ссылкой на ID функции. Звук — по `sounds.md`.
3. Если в базе чего-то нет и совет опирается на общие знания — **явно пометить**: «это общее знание, в твоей базе такого приёма пока нет». Не выдавать своё за выученное.
4. Для сценария можно предложить текст целиком, разметив, где какая функция работает. Текст целиком перед ответом прогнать через `humanizer-ru`, как в режиме 5.

## Режим 5. Сценарий: «напиши сценарий рилса про …»

1. Уточнить, если неясно: тема, для кого, что зритель должен сделать в конце, длительность. Голос и тон — из профиля пользователя (если есть проект с `harness.config.json` или `reels.config.json`).
2. Собрать структуру из функций категорий С, Х, У (например, С-02 как каркас, Х-01 как хук, У-01 для списка).
3. Написать текст **по секундам**, как говорят вслух: короткие фразы, без канцелярита, речь с первого кадра. Темп ~2,5–3 слова в секунду: 30 с ≈ 80 слов, 50 с ≈ 140 слов.
4. **Очеловечить текст навыком `humanizer-ru`** (Skill `humanizer-ru`, установлен в `~/.claude/skills/humanizer-ru/`). Прогнать через него только произносимый текст и текст на экране, без разметки. Режим — редактура своего черновика: убрать канцелярит, воду и нейросетевую манеру, не меняя фактов, цифр, хука и кодового слова. Сценарий пишется под живую речь, поэтому разговорные обороты оставлять. Если навыка нет — сказать об этом и вычитать по тем же правилам вручную.
5. Рядом с каждым куском — разметка для монтажа: какая функция, какая графика над головой, где склейка, где звук. Так сценарий сразу превращается в раскадровку.
6. Дать 2–3 варианта хука на выбор (тоже после `humanizer-ru`).
7. Если приём взят не из базы — пометить как общее знание.

При разборе рилсов всегда выделять и функции сценария (категория С): как построена первая фраза, обещание, переходы между пунктами, концовка, призыв.

## Режим 6 (по желанию). Статистика и своя рилсология через Apify: «подтяни просмотры», «загрузи мои рилсы»

Режим не обязателен: без него навык работает, просто вместо просмотров в разборах будут лайки. Instagram без входа отдаёт лайки и комментарии, а просмотры даёт только через Apify (`apify/instagram-scraper`, оплата за результат, около $0.003 за рилс).

**Подключение.** Токен Apify пользователь кладёт сам: переменная `APIFY_TOKEN` или файл `~/.config/reelsology/apify_token`. Токен не печатать и не просить вставить в чат. Если токена нет, но подключён плагин Apify, сделать то же через плагин (`call-actor` с теми же параметрами). Если нет ни того, ни другого, сказать, что режим недоступен, и продолжать без него. Каждый запуск тратит деньги пользователя: называть число рилсов и примерную сумму, а если рилсов больше 50, сначала спросить.

**Просмотры для базы.**
```bash
python3 ~/.claude/skills/reelsology/scripts/apify.py stats            # все разборы
python3 ~/.claude/skills/reelsology/scripts/apify.py stats ID ID      # только новые
```
Скрипт пишет `views`, `likes`, `published` и `stats_as_of` во frontmatter разборов и собирает `stats.md`. После каждого нового пакета запускать для новых ID. При сравнении роликов учитывать возраст: ролик моложе двух недель ещё набирает просмотры.

**Своя рилсология** — когда пользователь хочет разобрать свои рилсы (или рилсы своего проекта) рядом с базой:
1. `python3 scripts/apify.py own <ник> [N]` выдаёт последние N рилсов (по умолчанию 12) с просмотрами и лайками, от лучших к худшим. Показать список и спросить, какие разбирать. По умолчанию 3 сильных и 3 слабых: так видна разница.
2. Каждый выбранный рилс пройти через режим 1, как обычно, с пометками `kind: свой` и `owner: <ник>` в разборе. Если приём уже есть в базе, новую функцию не заводить, а дописать в карточку раздел «Опыт применения»: какой ролик, сколько просмотров, сработало или нет.
3. Для разобранных запустить `python3 scripts/apify.py stats <ID…>`: их цифры попадут в `stats.md` с пометкой «свой».
4. Итог для пользователя: какие функции и принципы есть в сильных своих роликах и каких нет в слабых. Так база проверяется на своей аудитории, а не только на чужих роликах.

Разборы своих рилсов пользователя можно коммитить: это его контент. Видео всё равно остаётся в `work/`.

## Режим 7. Библиотека звуков: «собери библиотеку звуков», «вырежи звуки из этих рилсов», «сохрани этот звук»

У каждого пользователя своя библиотека: папки по задаче, файл назван так, чтобы было понятно, когда его ставить (`trevozhnye-chasy.wav`, `svush-dlya-skleyki.wav`). Лежит вне навыка, путь запоминается в `~/.config/reelsology/config.json`. Всё делает `scripts/sfx.py`, подробности в его шапке.

**Когда предлагать.** Библиотеки ещё нет (`sfx.py where` → «нет библиотеки»), а разговор дошёл до звука: подбираем звуки к ролику, разбираем рилс про звуки, человек спрашивает, где взять звук. Предложить одной фразой: «Хочешь, соберу тебе свою библиотеку звуков? Пришли рилсы или файлы со звуками, которые нравятся, я вырежу их, назову по задаче и разложу по папкам. Потом буду брать оттуда при монтаже». Библиотека есть, и в монтаже подобран новый звук, который понравился (найденный в Mixkit, присланный файл, сгенерированный): спросить «Сохранить в библиотеку?» и на «да» сделать `sfx.py add`.

**Создать.** Спросить, где держать (по умолчанию `~/reels-sfx`, отдельно от проектов, чтобы ею пользовались все ролики), затем `python3 scripts/sfx.py init <путь>`. Создаются 10 папок: переходы, напряжение, акценты, мемные, правильно/неправильно, интерфейс, деньги, цензура, мультяшные, экшн/foley. Новую папку можно завести, просто указав её в `cut` или `add`.

**Из рилсов** (ссылки или файлы с любимыми звуками):
1. `python3 scripts/sfx.py scan <ссылка или slug> ...` скачивает рилс (через `intake.py`, если его ещё нет в `work/`), находит слова по времени (whisper), берёт только окна без голоса с запасом 0,1 с и делит их на отдельные звуки по громкости. Результат: `work/<slug>/sfx/candidates.md` (таблица звуков) и `sheet-N.jpg` (кадр на каждый звук, 12 на лист, слева направо).
2. Прочитать `candidates.md` и **все** листы кадров. Название звука почти всегда написано в кадре (подпись, карточка, дорожка), берётся оттуда. Если звуки идут подряд и подписи общие на блок (сетка карточек), то соединять соседние куски одного звука (три удара «бам-бам-баам» — один файл) и называть по порядку карточек и форме волны с пометкой `guess`. Если в рилсе автор говорит без пауз, звуков без голоса нет, и так и сказать. Мем-фразу с чужим голосом («A few moments later») не брать: это голос.
3. Записать `cuts.tsv` (формат в шапке `sfx.py`): папка по задаче, имя латиницей «что-за-звук-для-чего», в описании «когда ставить» по-русски, одной фразой, на языке монтажа (на что ставить: склейка, цифра, плохая новость…). Одинаковые звуки из двух рилсов не дублировать.
4. `python3 scripts/sfx.py cut cuts.tsv` режет, срезает тишину до атаки, делает фейды, выравнивает пик на −1 дБ, пишет WAV 48 кГц, прогоняет каждый клип через whisper и дописывает `index.json` и `INDEX.md`. Если скрипт пишет «whisper слышит», посмотреть кадр. Галлюцинации вроде «you», «Thank you», титров — это не голос; осмысленная фраза — убрать клип.
5. Ответ пользователю: сколько звуков и в каких папках (таблицей), из каких рилсов ничего не вышло и почему, какие названия с «≈» стоит проверить на слух. Открыть папку: `open <путь>` (в Finder пробел проигрывает файл).

**Из файлов.** Присланный звук: `sfx.py add <файл> <папка> <имя> "когда ставить" --src "откуда"`. Длинный файл с несколькими звуками: сначала `scan <файл>`, потом `cut`.

**В монтаже.** Прочитать `INDEX.md` библиотеки, выбрать звук по колонке «Когда ставить» и по `sounds.md`, скопировать в проект: `python3 ~/.claude/skills/reelsology/scripts/sfx.py use <имя> ... --to video/public/sfx`. Ставить началом файла на кадр события или на кадр раньше. Громкость по `sounds.md`. Нужного звука нет: найти (Mixkit, Freesound CC0, Kenney, CapCut) и предложить сохранить в библиотеку.

**Порядок.** Переименовал звук или переложил в другую папку — `sfx.py index` уберёт из списка пропавшие файлы, а неописанные покажет внизу `INDEX.md`. Проверить всю библиотеку на голос: `sfx.py check`.

## Техника: от дубля до площадки

Только техника. Стиль, графику, шрифты и голос выбирает пользователь в своём проекте. Здесь — как не испортить картинку и звук по дороге.

Команды ниже запускаются из папки `video/` проекта монтажа. Проекта нет: сначала раздел «Настройка». Полный порядок монтажа нового ролика лежит в проекте: `.claude/skills/new-video/SKILL.md`. Свой проект Remotion тоже подойдёт: скопируй туда `pipeline/scripts/*` в `scripts/` и `pipeline/starter/video/remotion.config.ts`, а `FootageOnly.tsx` зарегистрируй в `Root.tsx` для вырезки.

### Главное правило

**Ролик не сдаётся, пока `check.py` не сказал «meets the delivery standard».** Смотреть глазами на Mac недостаточно: QuickTime прощает всё, что ломает ролик на площадках. Именно так дошли до публикации все ошибки из `pipeline/references/incidents.md`.

### Разрешение — не уменьшать по дороге

- **Базово работаем с 4K.** `cut.py` и `assemble.py` пишут нарезку в разрешении исходника: 4K остаётся 4K.
- **Ничего не растягивается.** Дубль 1080p остаётся 1080p.
- Уменьшать можно только явно: `SIZE=1296x2304` — это потолок, не цель; меньший исходник он не трогает.
- Панч-ины кадрируют реальные пиксели 4K. Цепочка «4K → 1080 → увеличение» и была главной причиной мыла.
- Единственное финальное сжатие с потерями — в `deliver.sh`. Всё, что до него, — почти без потерь: нарезка crf 14, мастер crf 12, кадры Remotion в PNG.

### Порядок работы

1. **Проверить окружение**: `bash scripts/doctor.sh`.
2. **Повторы и фальш-старты**: `python3 scripts/chunks.py ../takes/1.MOV` → диапазоны в `DROP="a-b,c-d"`.
3. **Нарезка**:
   - по паузам: `python3 scripts/cut.py ../takes/1.MOV` → `public/footage.mp4`, `captions.json`, `keeps.json`. Печатает разрешение, `DURATION` и кадры склеек.
   - сегменты, выбранные по смыслу (несколько камер, лучшие дубли): `python3 scripts/assemble.py take.MOV seg.json out/edit.mov` → затем `cut.py` по этому файлу или прямо в `public/footage.mp4`.
4. **Композиция** (проект пользователя): панч-ин только на склейке из вывода `cut.py`; анимации только от `useCurrentFrame()`.
5. **Вырезка человека** (если есть постер за головой): `python3 scripts/matte.py N` или `A-B` для диапазона. Кадры рендерит Remotion (`FootageOnly`), не ffmpeg. rembg — **один процесс** (около 11 ГБ памяти); две тяжёлые задачи одновременно не запускать.
6. **Черновик**: `bash scripts/draft.sh` (540p, JPEG — только для просмотра, не для сдачи).
7. **Мастер — только после явного «да» пользователя**: `CHUNK=400 CONCURRENCY=8 caffeinate -i bash scripts/master.sh` → `out/final-master.mp4`. В конце сам вызывает `check.py`.
8. **Файлы площадок**: `bash scripts/deliver.sh ../edits/N/final-master.mp4` → `final-ig.mp4` (1080×1920) и `final-shorts.mp4` (1440×2560). Каждый проверяется `check.py --platform`.
9. **Архив**: `bash scripts/archive.sh ../edits/N`. Без архива ролик нельзя перерендерить, см. ниже.

### Ускорение

`SPEED=1.06` (в env или `reels.config.json → cut.speed`):
- видео — смешивание кадров (`framerate=fps=30`), **никогда** `setpts` + `fps=30`: выброшенные кадры дают микрорывок примерно дважды в секунду;
- звук — `atempo`, высота голоса сохраняется;
- ускорение делается в нарезке, а не в мастере: субтитры, склейки и композиция живут на ускоренной шкале.

### Архив и перерендер

`archive.sh` кладёт в `edits/N/project-state/`: `keeps.json` (точные склейки и все параметры нарезки), `captions.json`, `src/`, `reels.config.json` на момент рендера, вырезки `cut/`, `*.assemble.json`. Флаг `FOOTAGE=1` копирует и `footage.mp4`.

Перерендер:
```bash
KEEPS=../edits/N/project-state/keeps.json python3 scripts/cut.py
```
Затем вернуть `src/`, `cut/`, `captions.json` и `reels.config.json` из архива и собрать мастер. Конфиг — именно архивный: с текущим конфигом ролик однажды чуть не ушёл с субтитрами по 3 слова вместо 4.

Архив лежит **вне** проекта Remotion (`../edits`): копии `.ts/.tsx` внутри `out/` или `src/` ломают сборку.

### Чего не делать

- Не задавать `crf` в `remotion.config.ts` — он ломает звуковой wav-проход мастера. crf — только в `master.sh`.
- Не делать кадры для вырезки через ffmpeg: тон кожи уезжает на ~5 L* от того, что рисует Remotion.
- Не сопоставлять кадры вырезки с исходником через округление времени — только кадры самой композиции.
- Не рендерить одним проходом длинную композицию: падает после ~2400 кадров. Чанки + отдельный wav.
- Не использовать `-shortest` при сведении картинки и звука: обрезает видео.
- Не перерендеривать прошлые ролики без просьбы.

### Справка

- `pipeline/references/delivery-standard.md` — стандарт файла: цвет, звук, контейнер, ключевые кадры, safe-зоны, как проверить.
- `pipeline/references/incidents.md` — все ошибки, из-за которых ролики портились, и где каждая исправлена.

## Правила

- Карточка пишется так, чтобы по ней мог повторить приём монтажёр без доступа к исходному рилсу: числа (секунды, кадры при 30 fps, масштаб, громкость), а не «быстро» и «чуть-чуть».
- Каждая функция ссылается на источник с таймкодом.
- Чужие ролики, кадры и тексты не уходят в git и не используются в роликах пользователя — только для разбора. В карточке — описание приёма своими словами, без копирования текста автора дословно (короткая цитата для примера допустима).
- База — пользователя. Не удалять и не переписывать функции без её просьбы; спорное — уточнить.
- Звуки для монтажа сначала берутся из библиотеки пользователя (режим 7). Из рилсов в неё вырезаются только чистые эффекты, без голоса автора. Сами видео остаются в `work/`, в git не попадают.
